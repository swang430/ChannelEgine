# Channel Engine 系统架构与核心原理设计

## 1. 架构定位与设计初衷

**Channel Engine (MIMO OTA Simulator V4.4)** 是一款专为 5G/6G 系统和高阶 WiFi 演进而设计的信道建模与空口（Over-the-Air, OTA）仿真转换引擎。

传统的**传导测试 (Conducted Testing)** 将基站与终端直接用射频线缆连接，这要求信道仿真仪必须在其数字基带芯片内完成庞大的 3D 空间矩阵运算（统一的全量 CDL 模型）。然而，在真正的 **OTA 物理暗室环境**中，真实的辐射探头与空间自由传播已经构成了物理上的 3D 几何，这就要求软件平台必须具备“倒推解析”的能力。

**Channel Engine 存在的最大价值，就是充当“空间解码器（Spatial De-multiplexer）”**：它向上衔接纯数学、虚拟的 3GPP TR 38.901 标准模型，向下连接具体的测控暗室天花板探头阵列布局，并为通道仿真硬件（如 Keysight Propsim F64）计算出高精度的射频播放特征。

## 2. 核心系统模块边界

系统采用了严格的抽象分离设计，由两个核心 Package 构建出完整的流水线框架：

*   **`channel_model_38901 / wifi_channel_model` (信道生成核心库)**：
    *   **职能**：依据数学和标准协议（3GPP，TGax），生产目标参考信道（H_target）。
    *   **特性**：这是完全与设备和硬件无关的模块。它支持概率随机过程（Stochastic）生成，也支持加载由协议定义的确定性模型参数（CDL / SCME系列）。
*   **`mimo_ota_simulator` (OTA 投影与仿真层)**：
    *   **职能**：管理用户自定义的实体环境（几根天线、什么阵型、多大暗室半径、线缆增益损耗）。将上方核心库产出的 3D 信道映射（Mapping）到这套物理设施上。
    *   **关键输出**：`A_Matrix` (发射侧探头注入权重矩阵)、提取带有真实多普勒偏移的单射线组件（Ray Components），并转化为时间序列的 `.asc` 硬件驱动流文件。
*   **交互接口 (`app.py`, `gui.py`)**：
    *   为最终工程师提供便捷直观的交互表盘。不仅负责下接配置底层结构，还负责在 UI 层渲染物理可视化的验证图表（如探头热力极坐标图、PDP响应、空间相关性协方差图表等）。

## 3. 信道建模架构：宏观大尺度(LSP)与微观小尺度(SSP)

对于新架构的接手者，必须理解框架中独创的 **“Hybrid（混合）模型思想”**：

在真实应用中，纯纯的 3GPP 随机模型难以在实验室精确复现测试结果；而纯粹的独立确定性模型（如 CDL-A）又丢失了大尺度环境带来的一些宏观约束（如不同地貌特有的路径衰减差异）。在 Channel Engine 内：
1. **LSP (大尺度参数)**：引擎强制计算用户指定场景（如 UMa 城市宏基站）下的大尺度约束（Shadow Fading, Pathloss, RMS 时延/角度扩展等）。
2. **SSP (小尺度参数/簇)**：使用 LSP 的框架参数或指定的理论模型表，生成独立的簇结构（Delay, Power, 3D 辐射角）。如果设置了 `use_median_lsps=True`，所有的随机数种子运算会被冻结为中值，以便供硬件验证团队截取出 100% Deterministic 的复现信道。

## 4. OTA 合成的绝对枢纽：深入理解 `A_Matrix`

系统计算过程中产生了多个矩阵，但作为架构师必须清楚：**`A_Matrix` 是整个系统的唯一工程真理。**

*   **`H_target`**：3GPP 虚拟的 3D 通道目标，纯理论参考标的物。
*   **`B_Matrix`**：暗室内真实的物理电磁波传播响应（从发射探头穿过空气传播到被测物中心）。这个矩阵靠大自然发挥作用，不对硬件编程。
*   **`A_Matrix` (发射映射矩阵)**：这正是我们需要写进信道仿真硬件（如 Keysight F64）去调控的数字指令！由于暗室内的微波信号最终会重叠为 $H_{eff} = B \\times A$，那么这里的 $A$ 将承担起“把全量 3D 空间结构碾碎降维”的重任。

### 为什么通道仿真仪里跑的不是统一的 CDL？
一根单一的物理射频线，无法传递“角度”信息，只能传递一条 1D 信号（带有特定时延和强幅变化的时变波形）。针对基站射频口到特定暗室探头口的通道网络，`A_Matrix` 内部将其重构为了成百上千条互不相干的独立 **TDL（Tapped Delay Line，抽头延迟线）**。

在这些多通道的独立 TDL 参数上，完美兼顾了宏观映射与微观修正：
1. **复数模 (Magnitude) = 宏观散射投影**：某探头正对着 3GPP 设定的来波角 (AoA)，它那一路的 TDL 就被高斯算法分去了巨大的功率权重。
2. **复数辐角 (Phase) = 微观阵列相位阶梯差**：虽然基站的四根发射天线都发向同一个宏观探头，但这四路的 TDL 被赋予了截然不同的静态几何相位差（Phase Shifts），完美保留并发扬了发射端天线物理间距带来的空间正交性，**从而让 5G 基站的下行波束赋形（Beamforming）技术能在暗室内被真实、成功地捕获并测试。**

## 5. 重构瑞利快衰落：Ray-Level 合成算法与拍频推演

硬件导出程序（`.asc` 控制流生成）使用了突破传统极限的 **“Ray-Level Synthesis（射线级合成）”** 技术路线。接手者需悉知，Channel Engine 的通道切片**绝不是赋予一个固定了幅度和多普勒周期的干瘪死波**。

由于 3GPP 中存在 “Angle Spread（角度展宽）”，一个经典的 Delay 簇实际由空间中微小的物理发散导致。我们针对任意一个 Cluster 抽头，做了深度的处理闭环：
1. **分裂**：强行打散出 20 条附带发散角度夹角的子射线 (Sub-Rays)。
2. **独立推算 Doppler**：因为有细微的 $\\Delta\\theta$ 夹角差差异，这 20 条子射线朝向终端运动矢量的多普勒频移 $f_d$ （譬如有的+88Hz，有的+92Hz）全部都不一致。
3. **拍频大合唱**：导出程序基于上述参数执行时域叠加运算（Sum/Einsum）。这堆拥有不齐等微小频率偏差而随机游走的波组合在一起时，在时间轴上形成了极具破坏性的**拍频效应 (Beat Frequency)**。

至此，在完全没有预埋“瑞利函数包络公式”进行强计算的前提下，纯靠 3D 几何特征的频移偏差，在时间维度的微小延迟抽头上完美复现并刻画出了 **降幅深达数十分贝的经典 U 型瑞利深衰落坑（Rayleigh deep fading）！** 这赋予了信道仿真数据无比真实的物理生命力。

## 6. 后期维护建议与接口扩展边界
1. **系统预失真模块 (Predistortion/Calibration)**：
    当环境增加新的线缆或更换探头时，只需要提供外部 `.csv` 表单进行路损和相位参数插入。在 `exporters.py` 内部生成波形时，这些影响将会以 `1 / System_Response` 的共轭翻转形式强制反乘进 `A_Matrix` 的复数内部，这确保了到达空中的波前无损、且外部校准过程完全不必干扰核心算法层的开发。
2. **算法增加**：
    若未来出现需要更换基站预编码映射模型、或升级 WiFi 802.11be 等新标准的情况，新接入层的全部实现逻辑请内聚包含于 `wifi_channel_model` 或 `channel_model_38901` 之内，外壳程序只需扩增 API 配置字（Config Data Models）即可，核心的 OTA 物理并联算法网络（`simulator.py`）不必做任何降维运算重构。
